## SAN 条填充错位修复（2026-06-27 晚）

**问题根因：** 原始代码用体力条公式（`maxSan * 0.625`）计算高度，但 SAN=100 时只得 62.5px，条太矮且填充坐标和容器不对齐。

**修复方案：** 完全切换为血量条逻辑（`drawHUD` 的 health bar 分支）：
- Sprite 改用血量条 tile（offset 268 而非 256）
- `barInnerH = 168 + (maxSan - 100)` = 168px（maxSan=100 时）
- `fillH = (int)(san/maxSan * barInnerH)`
- `fillRect.Y = sanVec.Y + 16 + 32 + barInnerH - fillH`（完全与原版一致）
- 容器底帽 Y = `sanVec.Y + 224 + (maxSan - 100) - 64`
- `staminaRect.Draw` 加上 `staminaRect.Bounds` 源矩形参数（与原版一致）

编译：0 错误，自动部署至 Mods。

## 爷爷跑远卡住修复（2026-06-27 晚）

**问题根因（3 处）：**
1. `WoodcutterScanner.ScanRadius = 25`（51×51 格！），`ScythingScanner.ScanRadius = 25`，爷爷会选 25 格外树木/作物为目标，一路跑过去
2. `TransitionTo(Orbiting)` 时未清空工作队列（`centerQueue`/`_targetQueue`），导致回到 Orbiting 后再工作时重选旧目标
3. Leash 检查只查爷爷离玩家距离，未查**目标**离玩家距离（玩家走开后目标过期）

**修复（4 个行为文件 + 2 个 Scanner）：**
- `WoodcutterScanner.ScanRadius`：25 → **8**（17×17 格，和耕地一致）
- `ScythingScanner.ScanRadius`：25 → **8**
- 所有 `TransitionTo(State.Orbiting)` 加入 `centerQueue?.Clear()` / `_targetQueue?.Clear()`
- Leash 检查加强：同时检查 `distToPlayer > LeashRadius` **和** `targetDistToPlayer > LeashRadius`
- 去掉所有 `WorldPosition` 轨道同步（orbit 在屏幕空间计算，`WorldPosition` 不同步也无害，Leash 对 Orbiting 状态不触发）
- 去掉 `TickOrbiting` 里所有过时注释

编译：0 错误 0 警告，DLL 已部署到 Mods 目录。

## 浇水动画 Bug 修复（2026-06-27 晚）

**问题现象：** 爷爷浇水时，玩家面前也会出现水流流下的精灵动画。

**问题根因：** `WateringExecutor.WaterArea` 原实现创建了一个临时浇水壶，并把它赋值给 `player.CurrentTool`，然后调用 `can.DoFunction(...)`。`DoFunction` 会触发玩家精灵的浇水工具使用动画（包括水流动画），导致玩家面前也出现了水花效果。

**修复方案：**
- `WateringExecutor.cs` 完全重写：不再触碰 `player.CurrentTool`，改为直接设置 `dirt.state.Value = 1`（浇水状态）
- 手动在目标格子位置创建水花 `TemporaryAnimatedSprite`（纹理索引13，即 `Game1.animations` 水花动画），位置基于 tile 坐标而非玩家坐标
- `GrandpaWatererBehavior.cs` 同步更新 `WaterArea` 调用签名（去掉 `player` 参数）
- 浇水音效仍在 `GrandpaWatererBehavior.TransitionTo(State.WateringTile)` 里播放，不受影响
