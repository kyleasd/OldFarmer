## 修复"怪物附近有矿石时爷爷打不到"
- **用户反馈**：怪物附近有矿石时，爷爷虽然去攻击了，但打不到怪物。
- **根因分析**：从 SDV 反编译源码（E-riCA0/StawdewValley 1.5.6）找到 `GameLocation.damageMonster` 内部检查链：
  1. `GetBoundingBox().Intersects(areaOfEffect)` — AoE 以怪物为中心，必定通过。
  2. `isInvincible()` — 玩家挥镐/挥剑设了无敌帧，`isBomb=false` 时伤害被跳过。
  3. **`isMonsterDamageApplicable(who, monster, …)`** — 检查 `who.CurrentTool`，玩家拿镐子挖矿时返回 false → `isBomb=false` 的伤害被**静默跳过**。这就是"矿石附近打不到"的根因。
  4. `hitWithTool(who.CurrentTool)` — 特定怪物+工具组合（如 Rock Crab + 镐子），返回 true 时整个 damageMonster 返回 false。
- **条件 #2/#3 的结构**：`(isBomb || isMonsterDamageApplicable(…)) && (!isInvincible() || isBomb)` — `isBomb=true` 同时绕过 #2 和 #3。
- **修复**：`DealDamage` 中非 Mummy 的 `damageMonster` 调用从 `isBomb=false` 改为 `isBomb=true`。
  - 绕过 `isMonsterDamageApplicable` → 不再依赖玩家手持什么工具
  - 绕过 `isInvincible()` → 不受玩家攻击设的无敌帧影响
  - 绕过 `Bug.isArmoredBug` 检查（条件为 `isArmoredBug && !isBomb`）→ 移除了临时关闭/恢复 isArmoredBug 的代码，简化为直接调用
  - `isBomb` **不影响伤害值和击退**（那些由 minDamage/maxDamage/knockBackModifier 控制）
  - `hitWithTool` 不受 `isBomb` 影响，但只影响特定怪物+工具组合，不是矿石场景的通用问题
- 编译：0 警告 0 错误，已自动部署。
